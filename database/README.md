# Database

## انتخاب آغازین

Cloudflare D1 دیتابیس رابطه‌ای اولیهٔ پروژه است. مدل داده بر پایهٔ رابطه‌های روشن، constraintها و queryهای قابل ایندکس طراحی می‌شود. D1 منبع حقیقت داده‌های تراکنشی کاربر خواهد بود.

## تفکیک مسئولیت

- schema/: مستند طرح منطقی، جدول‌ها، رابطه‌ها و indexهای مورد انتظار.
- migrations/: تنها مسیر مجاز تغییر ساختار دیتابیس؛ هر تغییر با SQL نسخه‌بندی‌شده.
- seeds/: داده‌های پایهٔ قابل تکرار، بدون اطلاعات واقعی کاربران.
- fixtures/: دادهٔ ساختگی برای تست و توسعه.

## دامنه‌های دادهٔ اولیه

- هویت و حساب: کاربران، هویت تلگرام، sessionها و تنظیمات.
- محتوای آموزشی: زبان، سطح، مسیر، درس، واحد و نسخهٔ محتوا.
- تمرین و ارزیابی: نوع تمرین، سؤال، گزینه‌ها، تلاش‌ها و پاسخ‌ها.
- پیشرفت: وضعیت تکمیل، امتیاز معتبر و رویدادهای لازم برای بازسازی پیشرفت.
- واژگان: مدخل‌ها، ارتباط آن‌ها با درس و وضعیت مرور هر کاربر.
- عملیات: idempotency، outbox jobها، مصرف AI و audit eventهای محدود.

## قواعد داده

- migrationها منبع حقیقت ساختار هستند؛ migration اعمال‌شده ویرایش یا بازنویسی نمی‌شود.
- برای هر رابطهٔ پرتکرار index متناسب با query واقعی تعریف می‌شود؛ index بدون workload اضافه نمی‌شود.
- queryها parameterized هستند.
- زمان‌ها در UTC ذخیره و در رابط کاربری محلی نمایش داده می‌شوند.
- شناسهٔ Telegram به‌صورت عدد صحیح ۶۴بیتی در D1 ذخیره می‌شود؛ از تبدیل ناامن یا بریدن شناسه جلوگیری شود.
- فایل باینری در D1 قرار نمی‌گیرد؛ فقط metadata، مالکیت، اندازه، نوع و object key ذخیره می‌شوند.
- دادهٔ تست باید ساختگی باشد. هیچ secret یا دادهٔ شخصی واقعی در seed و fixture قرار نمی‌گیرد.
- عملیات پاک‌سازی، export، retention و حذف حساب باید از ابتدا در طراحی داده قابل پیاده‌سازی باشند.

## نکتهٔ ظرفیت

هر D1 database پردازش query تک‌ریسمانی دارد. یک دیتابیس مشترک را برای یک میلیون کاربر فعال روزانه ظرفیت‌سنجی‌شده فرض نمی‌کنیم. در صورت رشد، ابتدا queryها، batchها، indexها و read replication بررسی می‌شوند؛ سپس partitioning یا جداسازی دیتابیس‌ها بر پایهٔ workload اندازه‌گیری‌شده طراحی خواهد شد.

## ابزار ORM

Drizzle می‌تواند لایهٔ کمکی TypeScript باشد، اما SQL migrationها canonical می‌مانند. پیش از تثبیت ORM باید نوع داده‌ها، constraintها، batch، transaction و اجرای migration روی D1 محلی و محیط آزمایشی تست شوند.
