# Test Strategy

این پوشه برای آزمون‌های مستقل و خودکار است. تا زمانی که کد اجرایی ساخته نشده، وجود این ساختار به معنی اجرای تست یا عبور از آن نیست.

## لایه‌های آزمون

- unit/: قواعد خالص learning-core، validation و use caseها.
- integration/: ارتباط backend با D1، R2 و صف‌ها در محیط شبیه‌سازی‌شده/آزمایشی.
- e2e/: مسیرهای واقعی Mini App تا API.
- security/: Telegram initData، session، مجوزها، rate limit، upload و دسترسی غیرمجاز.
- load/: الگوی واقعی read/write، latency، contention در D1 و رفتار نزدیک سقف سهمیه.

## دروازهٔ پذیرش

هیچ قابلیت نباید صرفاً به دلیل build موفق، آمادهٔ انتشار محسوب شود. تست مسیر موفق، مسیر خطا، ورودی نامعتبر، تکرار درخواست، retry و بازیابی باید متناسب با ریسک قابلیت اجرا شود.

هر گزارش باید commit SHA، نسخهٔ ابزار، محیط، فرمان اجرا، نتیجه و تست‌های اجرا نشده را مشخص کند.
